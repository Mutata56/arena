портфель
как опубликовать java-path на GitHub
к ТЗ
Публикация ручная и это осознанно: репозиторий с решениями твой, историю в нём пишешь ты. arena туда не коммитит и не пушит ни при каких условиях, даже когда очень хочется. Ниже порядок действий целиком, от первого коммита до ссылки, которую можно положить в резюме. Спешить некуда: пока проектов один или два, публиковать особо нечего.
1

Посмотреть, что вообще собралось

Репозиторий уже существует, его завела arena при первой задаче. В tasks лежат микрозадачи по нодам, в projects проекты по ТЗ этапов. Это и есть портфель.

cd ~/projects/java-path
git status
git config core.quotepath false

Последняя строка нужна один раз: без неё git показывает русские имена папок кракозябрами, а у нас так названы почти все каталоги.

2

Убрать лишнее из индекса

В папках задач лежат служебные файлы arena и следы компиляции. В портфеле им делать нечего. Заведи .gitignore в корне репозитория:

.arena.json
.arena-tz.json
*.class
out/
target/
.idea/

Отдельно пройдись глазами по своим файлам: имён серверов, логинов и данных с работы в публичном репозитории быть не должно. Складская тематика в задачах выдуманная, а вот случайно вставленный кусок реального лога уже нет.

3

Представиться git

Имя и почта попадут в каждый коммит и будут видны публично. Почту можно взять скрытую, GitHub выдаёт такую в настройках профиля.

git config user.name "demo_user"
git config user.email "твоя@почта"
4

Первый коммит

Один общий коммит на всё, что уже написано, дальше по одному на задачу или проект. Сообщения человеческие: что сделал, а не «update».

git add .
git commit -m "Задачи и проекты первых этапов"
5

Завести репозиторий на GitHub

На github.com кнопка New repository. Имя java-path, описание в одну строку, видимость Public. Галочки Add README, Add .gitignore и Choose a license НЕ ставь: файлы уже есть локально, а пустой README с той стороны потом придётся сливать руками.

6

Ключ SSH, если его ещё нет

По SSH пушить удобнее: пароль не спрашивают, токены не протухают.

ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519 -C "java-path"
cat ~/.ssh/id_ed25519.pub

Содержимое второй команды копируется в GitHub: Settings, SSH and GPG keys, New SSH key. Проверить связь: ssh -T engineer1@example.invalid, в ответ должно прийти приветствие с твоим ником.

7

Привязать и отправить

Адрес берётся со страницы репозитория, вкладка SSH.

git remote add origin engineer1@example.invalid:ТВОЙ_НИК/java-path.git
git branch -M main
git push -u origin main

Дальше достаточно git push. Если git ругается, что ветка уже существует и расходится, значит на GitHub всё-таки создался README: забери его командой git pull --rebase и повтори push.

8

Сделать README витриной

Это первое и часто единственное, что открывает человек по ссылке из резюме. Пара абзацев про то, что здесь лежит и зачем, список проектов по ТЗ с одной строкой описания на каждый, и чем каждый интересен технически. Про учебный характер писать честно: джуна с честным учебным портфелем читают лучше, чем с чужим скопированным.

Для каждого проекта по ТЗ уже есть README с постановкой: на него можно просто сослаться из корневого.

9

Ритм

Коммит после каждой зелёной задачи, пуш раз в несколько дней. Ровная лента коммитов на протяжении месяцев говорит про тебя больше, чем один большой коммит в день перед собеседованием.

Проект по ТЗ имеет смысл коммитить дважды: как сдал и после доработок по ревью. Видно, что ты умеешь принимать замечания и доводить работу.

Если что-то пошло не так, ничего страшного не случилось: репозиторий локальный, и его всегда можно отвязать от удалённого (git remote remove origin) и начать этот шаг заново.
