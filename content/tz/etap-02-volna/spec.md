# Волна отбора по маршруту склада

## Бизнес-контекст

Склад собирает заказы волнами. Отборщик идёт с тележкой по проходам и снимает товар с ячеек,
пока тележка не наберётся. Маршрут не произвольный: он идёт змейкой, потому что разворачиваться
в узком проходе дороже, чем пройти его до конца. Когда волна закрыта, WMS отправляет в ERP
короткое сообщение о том, что и откуда сняли.

Ты пишешь ту часть, которая считает план: сколько снять, из каких ячеек, в каком порядке
и на сколько волн это разложится. Это ядро реального потока, только без базы и без сети.

## Функциональные требования

Один класс `Wave`, все методы статические (классы и объекты идут на следующем этапе).
Склад приходит матрицей: строка это проход, столбец это ячейка в проходе, значение это
остаток в штуках. Строки могут быть разной длины, это нормально: проходы на складе разные.

1. `static int totalStock(int[][] stock)` возвращает суммарный остаток по всему складу.
2. `static int[][] pick(int[][] stock, int need)` строит план отбора: массив строк вида
   `{проход, ячейка, сколько снять}` в том порядке, в каком отборщик их обойдёт.
   Обход змейкой: проход с чётным индексом идёт слева направо, с нечётным справа налево.
   Из ячейки берётся не больше, чем в ней лежит. Пустые ячейки в план не попадают.
   Если товара меньше, чем просят, собирается сколько есть. Входной массив не меняется.
3. `static int waves(int picked, int capacity)` возвращает количество волн: сколько раз
   придётся вывезти тележку вместимостью `capacity`, чтобы увезти `picked` штук.
4. `static String route(int[][] picks)` возвращает маршрут одной строкой (формат ниже).
5. `static String verdict(int need, int picked)` возвращает код строки заказа:
   `NOSTOCK`, если не собрано ничего, `PARTIAL`, если собрано меньше, чем просили,
   и `OK`, если собрано столько же или больше.
6. `static String statusText(String code)` переводит этот код в текст для оператора:
   `OK` это «собрано», `PARTIAL` это «собрано частично», `NOSTOCK` это «нет остатка».
7. `static String message(String order, int[][] picks, int capacity)` собирает
   интеграционное сообщение для ERP (формат ниже).
8. `static String message(String order, int[][] picks)` то же самое, но с вместимостью
   тележки по умолчанию: константа `DEFAULT_CAPACITY`, десять штук.

## Ограничения

Это ТЗ этапа «Базовый синтаксис», и оно должно быть решено средствами этапа.
Обязательно используй:

- двумерный массив и вложенные циклы для обхода склада;
- `switch` в `statusText`: классический или новый, на твой вкус, но не цепочка `if else`;
- перегрузку метода: две версии `message`, короткая зовёт длинную, а не копирует её;
- целочисленную арифметику в `waves`: без `double` и без `Math.ceil`, на больших числах
  дробная арифметика врёт;
- свои тесты на JUnit 5 в папке `tests`: минимум шесть проверок, и все зелёные.

Чего делать не надо: своих классов кроме `Wave`, коллекций, потоков и работы с файлами.
Всё это дальше по роадмапу, здесь оно только запутает.

## Формат ввода и вывода

Маршрут (`route`): элементы через точку с запятой, проход и ячейка нумеруются с единицы,
количество идёт после `x`. Пустой план это пустая строка.

```
1.3x5;2.1x3
```

Сообщение (`message`): одна строка, поля через точку с запятой, порядок фиксирован.
`LINES` это количество строк плана, `QTY` это сколько штук всего снято,
`WAVES` считается методом `waves`.

```
ORDER=A-100;LINES=2;QTY=8;WAVES=1;ROUTE=1.3x5;2.1x3
```

Кривой вход это `IllegalArgumentException`, а не тихий ноль:

- `stock` равен null или содержит отрицательный остаток;
- `need` или `picked` отрицательные;
- `capacity` меньше единицы;
- `order` пустой или null;
- `code` в `statusText` неизвестный или null.

## Критерии приёмки

- Скрытые тесты зелёные. Они гоняются по этому же публичному интерфейсу, поэтому имена
  и сигнатуры менять нельзя.
- Обход написан один раз и переиспользован, а не скопирован в `route` и `message`.
- Имена говорят о складе, а не о буквах: `aisle`, `cell`, `qty`, `left` понятнее, чем `a`, `b`, `x`.
- Проверки входа стоят в начале метода, до арифметики.
- Свои тесты покрывают не только счастливый путь: пустой склад, нехватку остатка,
  границы вместимости и хотя бы одно исключение.

## Примеры

Склад:

```
{{10, 0, 5},
 {3, 7}}
```

- `totalStock` даёт 25.
- `pick(stock, 8)` даёт `{{0, 0, 8}}`: первая же ячейка закрывает потребность.
- `pick(stock, 16)` даёт `{{0, 0, 10}, {0, 2, 5}, {1, 1, 1}}`. Второй проход идёт
  справа налево, поэтому после ячейки `0.2` отборщик снимает с `1.1`, а не с `1.0`.
- `route` от этого плана даёт `1.1x10;1.3x5;2.2x1`.
- `waves(16, 10)` даёт 2, `waves(20, 10)` даёт 2, `waves(0, 10)` даёт 0.
- `verdict(16, 16)` даёт `OK`, `verdict(20, 16)` даёт `PARTIAL`, `verdict(5, 0)` даёт `NOSTOCK`.
- `message("A-100", pick(stock, 16))` даёт
  `ORDER=A-100;LINES=3;QTY=16;WAVES=2;ROUTE=1.1x10;1.3x5;2.2x1`.
